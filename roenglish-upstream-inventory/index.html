    ROEnglishRE upstream inventory

    This is a read-only source inventory of ROEnglishRE revision 680a2f2126c8eb5872bf06cf441685c408ed1358. “Verified” means directly observed in that revision's files or in this repository's implementation; it does not mean that the upstream Windows scripts were executed or the resources tested in a client. “Unclear” identifies intent, runtime behavior, or compatibility that the source inspection does not establish.

    The detailed selection and compatibility reviews are in the Additions audit and the Addon audit. Both identify remaining unverified components; neither audit asserts complete browser compatibility.

    Integration before the runtime-generation work

    Verified at baseline 7a53448: images/remote/Dockerfile copied Translation/Renewal/data and SystemEN, then overlaid the corresponding Pre-Renewal trees when the build argument SET_PRERENEWAL=1. It also copied Additions/SystemEN/PetEvolution.lub. It did not run upstream generators or apply Compatibility or other Additions or Addons. images/remote/tests/check-roenglish.py checks the resulting base/Pre-Renewal translation hashes and PetEvolution, not the omitted layers. Repository overrides and mounted client resources may affect what is served separately from this build.

    Unclear: Upstream client-date compatibility does not establish compatibility with roBrowser, its Lua execution, the PHP RemoteClient, a particular GRF, or client patches. See docs/loose-client-resources.md for this repository's specific System/SystemEN and GRF fallback limitations. Parts of docs/deployment.md describe System paths and runtime merging differently from the Dockerfile and that more specific document; verify implementation before relying on those statements.

    Unclear: Whether the index offset, duplicate old-date copies and omissions are intentional. The observed algorithm must not be replaced silently by a simple chronological overlay if exact upstream behavior is required.

    Verified defects and limitations:

    • The prompt advertises default 20220406, but tests and sets date rather than cdate; an empty client-date input therefore does not reliably receive that default. Input is not validated.
    • Several all-in-one Lua copy paths omit lua files for effecttool, skilleffectinfo, stylingshop and CashEmotion, unlike the corresponding individual branches and the checked-in layout. The script also references Additions sources skillinfoz/skillid.lub, stateicon/stateiconinfo.lub and SystemEN/Signboard_C.lub that are absent at those paths in this revision.
    • The checked-in dated PrivateAirplane 20260520.lub and EquipmentProperties 202509.lub variants are not selected by date in the generator. The menu labels both mjolnir_10 and mjolnir_11 as 11; branch 12 actually copies mjolnir_11.
    • All-in-one map copying is not identical to the union of individual branches: for example the individual sch_lab branch requests a BMP that the all-in-one map branch does not request. A “Copied” indicator is set without checking successful copies, and xcopy /C continues after errors.

    Unclear: Whether missing sources and path discrepancies are intentional, what a particular Windows environment actually copies when an error occurs, and whether dated variants should be selected for any client. No generator was run.

In particular, the six Legacy Navigation tables load as Lua, but their monster and distance entries do not all match the assumptions of the client's navigation code.     The initial ROENGLISH_ADDITIONS=all implementation selects the additions listed explicitly in images/remote/roenglish-generate.php, not every file in the upstream Additions tree. The generator supplies datainfo/enumvar.lub for the base addrandomoptionnametable.lub; together the pinned originals execute as 254 numeric-keyed string entries under Lua 5.1. Client-local GRFs can still take precedence, so the actual displayed options depend on the loaded GRFs and server. Other client-loaded candidates, including hat effects, require format, dependency and version checks before they can safely be enabled. This is an open integration gap rather than a claim that the remaining files are incompatible. ROENGLISH_LEGACY_MAPS=1 selects the two upstream all-in-one legacy map/minimap choices; 0 leaves those additions out.

    The client also loads skillinfoz/jobinheritlist.lub before its skill tree. The pinned Additions source references five undefined job constants and stops under Lua 5.1. The generator supplies these five values from the pinned roBrowser's JobConst.js only in a generated copy, after checking the exact canonical source hash and one expected insertion point. The source and user overrides are left untouched. The resulting inheritance table has 148 numeric entries; the tests exercise both Renewal modes and the client's HTTP path. The chosen skill-tree data and displayed skills remain dependent on the loaded client and server data; this does not establish every version's full UI behavior.

    Similarly, the selected Additions/data/luafiles514/lua files/worldviewdata/worldviewdata_table.lub references six WORLD_MSGID keys (MSI_102_CH1_FILD1, MSI_2_CH1_ZERO1 through MSI_2_CH1_ZERO4, and MSI_DUN51) that were added in upstream commit d336ab454031fda5868e710cbf2435216474bff4 (8e71824234385c7cd5084ccbd6976c8dbeb44019) for 2025-08-02 but omitted from Translation/Renewal/.../worldviewdata_language.lub when worldviewdata_table.lub was moved into Additions/ (a2e9b9dd94511a345a730faad9fa988f182a8fa2). The generator restores those six upstream strings only in its generated copy of worldviewdata_language.lub after verifying the canonical source SHA-256 and a single replacement count, leaving the pinned source and user overrides untouched. With those six keys restored, all 424 Renewal and 384 Pre-Renewal WorldMap table entries resolve non-empty display strings under Lua 5.1.

    For the upstream HatEffect addition (selected by the Windows generator from 2024-04-17), the pinned HatEffectIDs.lub and HatEffectInfo.lub execute under Lua 5.1 and define 290 IDs and 265 effects. The same source directory's FootPrintEffectInfo.lub does not parse: its first invalid assignment is at line 214, and Type = STR = 4 occurs five times. The pinned client loads the footprint file after the other two. From 2024-04-17 the generator supplies those three client paths and repairs the five assignments only in its generated copy. It checks the source SHA-256 after CRLF-to-LF normalization and the replacement count before writing, preserving the source line endings; an unexpected source fails generation explicitly. The original source is unchanged. The corrected copy executes with 25 footprint entries. Correct display still depends on the server's IDs and on effect assets in the client GRFs. Tests check the date boundary, source immutability, Lua execution and HTTP paths.

    Other tools and Linux limits

    Verified: LuaConverter.bat invokes bundled luac.exe to produce .lub; the executable is a 32-bit Windows PE program. The script also mentions uncompressed .lub files. Tools/msgstringtable/encode.py and Tools/simplemsg/encode.py Base64-encode individual CSV fields into new CSV files. Repute and MacroReport batch wrappers call their jsonbson.py converters; the converters identify py-bson as a dependency. These tools use relative working-directory paths and produce output files when run.

    Porting limits: Windows batch commands, xcopy, code page 1252 and the bundled executable are not native Linux equivalents. Linux case-sensitive paths, spaces and legacy encoded non-ASCII path bytes require explicit handling; do not blindly normalize or transcode names. Reproduce or deliberately correct ordered overwrites, mode fallback, deletions, missing sources and menu behavior. Any replacement Lua compiler must match the target runtime's bytecode expectations; a .lub extension alone proves nothing. Nemo/WARP patches, GRF lookup and resource loading are separate from copying files. No native Linux port, Windows execution, generated output comparison or end-to-end client test was performed for this inventory.
